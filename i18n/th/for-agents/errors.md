# การจัดการข้อผิดพลาดสำหรับไคลเอนต์ AI {#error-handling-for-ai-clients}

SandBase ไม่มี schema ข้อผิดพลาดแบบเดียวที่ใช้ได้กับทุกที่ ให้แยกกรณีตามสถานะ HTTP ก่อน แล้วจึงแยกวิเคราะห์รูปแบบการตอบกลับ
ตามที่ระบุไว้สำหรับกลุ่ม endpoint นั้น อย่าคิดว่าทุกการตอบกลับจะมี `code`, `param`, `request_id` หรือ
ข้อความที่เจาะจง

## รูปแบบการตอบกลับสาธารณะ {#public-response-shapes}

middleware หลักของ `/v1/*` และ endpoint ของโมเดลหรือรีซอร์สหลายตัวจะส่งคืนข้อผิดพลาดแบบแบน:

```json
{"error":"organization rate limit exceeded"}
```

รีซอร์สของแพลตฟอร์ม Agents (`/v1/agents*`, `/v1/mcp-connections*`, `/v1/secrets*`,
`/v1/skills*`) จะส่งคืนออบเจ็กต์แบบ OpenAI ที่มี `code` คงที่ ดู [ข้อผิดพลาดของแพลตฟอร์ม Agents](#agents-platform-errors):

```json
{"error":{"type":"invalid_request_error","code":"invalid_request","param":null,"message":"invalid request"}}
```

เกตเวย์ที่เข้ากันได้กับ OpenAI จะคงรูปแบบข้อผิดพลาดที่เข้ากันได้กับ OpenAI ส่วน `POST /v1/messages` จะคง
รูปแบบข้อผิดพลาดที่เข้ากันได้กับ Anthropic:

```json
{
  "type": "error",
  "error": {
    "type": "invalid_request_error",
    "message": "max_tokens is required"
  }
}
```

## การจัดการสถานะ HTTP {#http-status-handling}

| สถานะ | ความหมาย | สิ่งที่ไคลเอนต์ควรทำ |
|---|---|---|
| `400` | อินพุตไม่ถูกต้องหรือพารามิเตอร์ไม่รองรับ | แก้ไขคำขอตาม schema ของ endpoint และโมเดลที่เลือก |
| `401` | ไม่มีข้อมูลรับรอง หรือข้อมูลรับรองไม่ถูกต้อง ถูกเพิกถอน หรือหมดอายุ | เปลี่ยนหรือหมุนเวียนข้อมูลรับรอง อย่าลองใหม่โดยไม่เปลี่ยนแปลง |
| `402` | ไม่สามารถชำระค่าคำขอได้ หรือถึงวงเงินการใช้จ่ายแล้ว | แก้ไขเรื่องการเรียกเก็บเงินหรือวงเงินของคีย์ก่อนลองใหม่ |
| `403` | ข้อมูลรับรองไม่มีสิทธิ์ หรือส่วนที่เข้ากันได้แมปความล้มเหลวด้านการใช้จ่ายเป็น 403 | ตรวจสอบรูปแบบข้อผิดพลาดที่ระบุไว้และใช้คีย์ที่ได้รับอนุญาต |
| `404` | ไม่พบโมเดลหรือรีซอร์ส | ตรวจสอบชื่อโมเดลหรือ ID ของรีซอร์สปัจจุบัน |
| `409` | สถานะของรีซอร์สขัดแย้งกัน | อ่านสถานะล่าสุดของรีซอร์สก่อนตัดสินใจว่าลองใหม่ได้อย่างปลอดภัยหรือไม่ |
| `429` | ขีดจำกัดคำขอขององค์กรหรือขีดจำกัดการทำงานพร้อมกันของวิดีโอ | ลองใหม่ด้วย exponential backoff แบบมีขอบเขตและ jitter |
| `500`, `502`, `503`, `504` | ความล้มเหลวชั่วคราวของ SandBase หรือต้นทาง | ลองใหม่เฉพาะเมื่อการดำเนินการนั้นทำซ้ำได้อย่างปลอดภัย |

## ข้อความเกี่ยวกับการยืนยันตัวตนและขีดจำกัดอัตรา {#authentication-and-rate-limit-messages}

ข้อความการยืนยันตัวตนที่ระบุไว้ ได้แก่:

- `missing API key in Authorization header`
- `invalid API key`
- `API key has been revoked`
- `API key has expired`

คีย์ที่จำกัดขอบเขตซึ่งถูกใช้นอกขอบเขตจะส่งคืน `403` พร้อม body แบบซ้อนแทน: `{"error":{"code":"insufficient_scope","message":"API key is not authorized for this endpoint","request_id":"..."}}` รีซอร์สของแพลตฟอร์ม Agents จะส่งคืน `code` เดียวกันในรูปแบบข้อผิดพลาดของตัวเอง

ข้อความขีดจำกัดอัตราที่ระบุไว้คือ `organization rate limit exceeded` (ขีดจำกัดคำขอต่อนาทีที่กำหนดให้องค์กร
ซึ่งใช้ร่วมกันโดย API key ทั้งหมดขององค์กร) ปัจจุบันการตอบกลับ `429` ไม่มีเฮดเดอร์ `Retry-After` หรือ
`X-RateLimit-*` และไม่มีค่าเริ่มต้น RPM หรือการทำงานพร้อมกันแบบสากลที่เผยแพร่ไว้

## การค้นหาโมเดลและรีซอร์ส {#model-and-resource-lookup}

ใช้ `GET /v1/models` เพื่อค้นหา ID ของโมเดลที่เปิดใช้งาน และใช้ `GET /v1/models/{id_or_name}` เพื่อตรวจสอบโมเดลก่อน
การรัน ให้ถือว่า ID ของรีซอร์สเป็นค่าทึบและตรวจสอบด้วยการดำเนินการ list หรือ get ที่เกี่ยวข้อง อย่าสร้าง
URL สำหรับ poll อื่นจากคำนำหน้าของ ID

## อัลกอริทึมการลองใหม่ {#retry-algorithm}

ใช้ exponential backoff แบบมีขอบเขตพร้อม jitter:

```text
delay = min(base_delay * 2^attempt, max_delay) + random_jitter
```

ใช้กฎต่อไปนี้:

- ลองใหม่สำหรับ `429` หลังจากหน่วงเวลาที่ไคลเอนต์คำนวณ
- ลองใหม่สำหรับการตอบกลับ `5xx` ชั่วคราวเพียงไม่กี่ครั้งและมีขอบเขต
- อย่าลองคำขอ `400`, `401`, `402`, `403` หรือ `404` ซ้ำโดยไม่เปลี่ยนแปลง
- ตรวจสอบ idempotency ก่อนทำคำขอสร้าง ทริกเกอร์ หรือการดำเนินการภายนอกซ้ำ
- เก็บเอาต์พุตบางส่วนไว้เมื่อสตรีมล้มเหลว แล้วตัดสินใจว่าจะดำเนินการต่อหรือเริ่มใหม่ได้อย่างปลอดภัยหรือไม่
- แจ้งสถานะ HTTP สุดท้ายและข้อผิดพลาดเฉพาะ endpoint ที่กรองข้อมูลละเอียดอ่อนแล้วให้ผู้เรียกทราบ

## ข้อผิดพลาดของแพลตฟอร์ม Agents {#agents-platform-errors}

Agents, Sessions, Skills, การเชื่อมต่อ MCP และ Secrets ส่งคืนรูปแบบข้อผิดพลาดเดียวกัน สำหรับรหัสส่วนใหญ่ `message` เป็นประโยคตายตัวที่ปลอดภัย ส่วน `invalid_request` อาจมีคำอธิบายสั้นๆ เช่น รูปแบบอินพุตหรือตัวเลือกใดที่ไม่รองรับ ให้แยกกรณีตาม `code` ไม่ใช่ `message`

```json
{"error":{"type":"invalid_request_error","code":"conflict","param":null,"message":"conflicting request"}}
```

`type` เป็น `authentication_error` สำหรับ 401, `server_error` สำหรับ 5xx และ `invalid_request_error` สำหรับกรณีอื่น

| HTTP | `code` | ความหมาย | สิ่งที่ควรทำ |
|---|---|---|---|
| 400 | `invalid_request` | ฟิลด์ผิดรูปแบบหรือไม่รู้จัก การตรวจสอบล้มเหลว หรือตัวเลือกไม่รองรับ | แก้ไขคำขอ อย่าลองใหม่โดยไม่เปลี่ยนแปลง |
| 400 | `skill_not_found` | Skill หรือเวอร์ชันที่อ้างอิงไม่พร้อมใช้งาน | แก้ไข `skills` ของ Agent |
| 401 | `unauthorized` | เฮดเดอร์ API key ขาดหาย ไม่ถูกต้อง หรือขัดแย้งกัน | ตรวจสอบ `Authorization` / `X-API-Key` |
| 402 | `spending_limit_exceeded` | ถึงวงเงินการใช้จ่ายของคีย์หรือยอดเงินขององค์กรหมดแล้ว | เติมเครดิตหรือเพิ่มวงเงิน |
| 403 | `insufficient_scope` | คีย์ถูกจำกัดขอบเขตและใช้รีซอร์สของ Agents ไม่ได้ | ใช้คีย์มาตรฐานที่สร้างจาก Console |
| 403 | `org_disabled` | องค์กรไม่ได้รับอนุญาตให้รัน Agents | ติดต่อฝ่ายสนับสนุน |
| 404 | `not_found` | ไม่มีรีซอร์สนี้ในองค์กรของคุณ | ตรวจสอบ ID |
| 409 | `conflict` | `row_version` ล้าสมัย สถานะไม่อนุญาตให้เปลี่ยนแปลง หรือใช้ `Idempotency-Key` ซ้ำกับ body ที่ต่างกัน | อ่านรีซอร์สอีกครั้ง แล้วจึงตัดสินใจ |
| 409 | `session_input_pending` | อินพุตก่อนหน้ายังส่งไม่เสร็จ | รอ อย่าส่งซ้ำด้วยคีย์ใหม่ |
| 409 | `session_input_expired` | การรับอินพุตหมดอายุ | ตรวจสอบประวัติก่อนส่งอีกครั้ง |
| 409 | `session_environment_unavailable` | สภาพแวดล้อมการรันไม่พร้อมใช้งาน | รอหรือสร้าง Session ใหม่ |
| 413 | `request_too_large` | request body หรือการกำหนดค่า Session ที่ตรึงไว้จาก body นั้นเกินขีดจำกัดขนาด | ส่ง body ที่เล็กลง อย่าลองใหม่โดยไม่เปลี่ยนแปลง |
| 429 | `quota_exceeded` | เกินโควตาของ Agents | ลองใหม่ภายหลัง |
| 502 | `executor_rejected`, `executor_contract_error` | ชั้นการรันปฏิเสธคำขอหรือตอบกลับอย่างไม่คาดคิด | ตรวจสอบการกำหนดค่า Agent แล้วลองใหม่ |
| 503 | `executor_unavailable`, `storage_unavailable`, `skill_unavailable`, `tenant_unavailable`, `tenant_provisioning_failed`, `authorization_unavailable`, `admission_unavailable`, `internal_error` | ระบบที่ต้องพึ่งพาไม่พร้อมใช้งานชั่วคราว | ลองใหม่ด้วย backoff และ `Idempotency-Key` เดิม |

อาจพบ `skill_runtime_incompatible` ได้เช่นกัน โดยจะส่งคืนเป็น 503 พร้อมข้อความ `internal error`

## ความล้มเหลวของการสตรีม {#streaming-failures}

หลังจากการตอบกลับแบบสตรีมเริ่มขึ้นแล้ว ความล้มเหลวอาจมาในรูปแบบสตรีมของโปรโตคอลแทนที่จะเป็น
สถานะ HTTP ใหม่ ให้ถือว่าสตรีมไม่สมบูรณ์ ปิดสตรีม เก็บเนื้อหาบางส่วนที่แอปพลิเคชันต้องใช้ไว้ และ
ลองใหม่เฉพาะเมื่อคำขอทำซ้ำได้อย่างปลอดภัย
