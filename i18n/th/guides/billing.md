# ราคาและการใช้งาน {#pricing-and-usage}

SandBase ใช้การเรียกเก็บเงินแบบจ่ายตามการใช้งาน ความพร้อมใช้งานของโมเดล สูตรราคา ตัวคูณแคช และค่าบริการเฉพาะ
ความสามารถอาจเปลี่ยนแปลงแยกกันได้ ดังนั้นการผสานระบบควรอ่านเมทาดาทาแบบสดแทนการพึ่งตารางราคา
ที่คัดลอกไว้

## การเรียก API ฟรีรายวัน {#daily-free-api-calls}

ทุกองค์กรได้รับการเรียก API ข้อมูลฟรี 100 ครั้ง (การค้นหา โซเชียล การดึงข้อมูลเว็บ อีคอมเมิร์ซ การเงิน) ต่อวันตามเวลา UTC
โควตานี้ใช้ร่วมกันโดย API ข้อมูลทั้งหมดที่มีสิทธิ์และคีย์ทั้งหมดขององค์กร และจะรีเซ็ตเวลา 00:00 UTC ส่วน LLM และ
โมเดลสื่อไม่มีสิทธิ์ API ข้อมูลบางตัวก็ไม่มีสิทธิ์เช่นกัน ได้แก่ตัวที่ราคาสูงกว่าหรือคิดราคาตามสูตร เช่น endpoint แบบแบตช์บางตัว endpoint สำหรับ crawl, Xiaohongshu PGY และเส้นทาง `kol-*` ของ Douyin Xingtu ซึ่งจะเรียกเก็บเงินตั้งแต่การเรียกครั้งแรก
หากต้องการตรวจสอบเครื่องมือ ให้รัน `sandbase_inspect` เครื่องมือที่มีสิทธิ์จะมี `pricing.free_quota` ส่วนเครื่องมือที่ไม่มีจะถูก
เรียกเก็บเงินเสมอ

- การเรียกภายในโควตาจะไม่ถูกเรียกเก็บเงิน และองค์กรที่มียอดเงินเป็นศูนย์ก็ยังใช้ได้
- หลังจากการเรียกครั้งที่ 100 การเรียกที่มีสิทธิ์จะยังทำงานต่อและเรียกเก็บเงินต่อครั้งตามราคาที่เครื่องมือแสดง โดยจะไม่ถูก
  ปฏิเสธหรือจำกัดอัตราเพราะใช้โควตาหมด
- การเรียกที่ไม่ได้ใช้จะไม่ยกไปวันถัดไป

ใน[เครื่องมือ SandBase MCP](/setup/) `sandbase_inspect` จะทำเครื่องหมายเครื่องมือที่มีสิทธิ์ด้วย `pricing.free_quota`
(`daily_limit`, `scope`, `resets`) ส่วน `sandbase_account` ส่งคืนโควตาของวันนี้เป็น `free_api_quota` พร้อม
`daily_limit`, `used_today`, `remaining` และ `resets_at` โดยจะละ `used_today` และ `remaining` เมื่อจำนวน
ไม่พร้อมใช้งานชั่วคราว หลังการรันชำระยอดแล้ว `sandbase_run` และ `sandbase_run_get` จะรายงาน `free_quota_status`:
`free` (อยู่ในโควตา), `overage` (เรียกเก็บเงินหลังใช้โควตาหมด) หรือ `degraded` (ไม่เรียกเก็บเงิน
เพราะไม่สามารถนับโควตาได้)

## จัดการการเรียกเก็บเงินใน Console {#manage-billing-in-the-console}

ใช้ **Developer → Billing** เพื่อดูยอดเงินคงเหลือ ซื้อเครดิต ตั้งค่าการเติมเงินอัตโนมัติ แลกคูปอง และจัดการการตั้งค่าการเรียกเก็บเงินที่มีให้
องค์กรของคุณ เปิด **Developer → Activities → Usage** เพื่อดูสรุปคำขอ โทเค็น และค่าใช้จ่ายระดับองค์กร

::: info ขอบเขตของ API สาธารณะ
endpoint สำหรับยอดเงินคงเหลือ การเติมเงิน การส่งออกข้อมูลการเรียกเก็บเงิน และการใช้งานทั่วทั้งองค์กร ปัจจุบันไม่ได้เป็นส่วนหนึ่งของ
API สาธารณะที่รองรับ อย่าทำให้คำขอเครือข่ายของ Console เป็นอัตโนมัติหรือพึ่งพาเส้นทางภายในของ Console
:::

## อ่านราคาโมเดลปัจจุบัน {#read-current-model-pricing}

ขั้นแรก ค้นหาโมเดลที่เปิดใช้งาน:

```bash
curl 'https://api.sandbase.ai/v1/models?q=gpt' \
  -H "Authorization: Bearer $SANDBASE_API_KEY"
```

จากนั้นขอ model card ฉบับเต็มของโมเดล:

```bash
curl https://api.sandbase.ai/v1/models/deepseek/deepseek-v4-flash \
  -H "Authorization: Bearer $SANDBASE_API_KEY"
```

endpoint แบบรายการได้รับการปรับให้เหมาะกับการค้นหา และตั้งใจละราคาโทเค็น แคช และการให้เหตุผลแบบละเอียด
ให้อ่านราคาโดยละเอียดของโมเดลที่เลือกจาก `model_card` ในการตอบกลับแบบรายละเอียด ไม่มีสูตรสากล
ที่ใช้ได้กับทุก LLM โมเดลสื่อ โมเดล embedding หรือความสามารถของ API

## ตรวจสอบค่าใช้จ่ายที่บันทึกไว้ของงานหนึ่งงาน {#check-one-task-s-recorded-cost}

เมื่อการดำเนินการส่งคืน ID ของงาน ให้ query บันทึกการชำระยอดของงานนั้น:

```bash
curl https://api.sandbase.ai/v1/tasks/{task_id}/cost \
  -H "Authorization: Bearer $SANDBASE_API_KEY"
```

การตอบกลับแยก `cost` ปัจจุบันออกจาก `estimated_cost` และรายงานว่าการชำระยอดเป็นค่าสุดท้ายแล้วหรือไม่
อย่าใช้ `cost` สำหรับการกระทบยอดการเรียกเก็บเงินจนกว่า `settled` จะเป็น `true` บันทึกงานเป็นข้อมูลสำหรับค้นหาเชิงปฏิบัติการ
ไม่ใช่บัญชีแยกประเภท ให้ใช้บันทึกการเรียกเก็บเงินและไฟล์ CSV ที่ส่งออกได้ใน **Developer → Activities → Usage**
สำหรับการกระทบยอดและการเก็บบันทึกระยะยาว

## แนวทางการควบคุมค่าใช้จ่าย {#cost-control-practices}

- ตรวจสอบ model card ปัจจุบันก่อนเริ่มเวิร์กโหลดใหม่
- ตรวจสอบ `capability_tags`, `supported_modes` และ `unified_schema` ทางเลือกที่ถูกกว่าจะมีประโยชน์ก็ต่อเมื่อ
  รองรับพฤติกรรมอินพุตและเอาต์พุตที่ต้องการ
- จำกัด context ของ prompt ที่ไม่จำเป็น และตั้งขีดจำกัดโทเค็นเอาต์พุตที่เหมาะสมเมื่อโมเดลที่เลือกรองรับ
- ถือว่าการแคชขึ้นอยู่กับแต่ละโมเดล ให้ตรวจสอบ model card และฟิลด์การใช้งานที่ส่งคืนแทนการคิดว่ามีส่วนลด
  ทั่วทั้งผู้ให้บริการ
- บันทึก ID ของงานเฉพาะสำหรับการค้นหาค่าใช้จ่ายของงาน สำหรับงาน `/v1/run` แบบอะซิงโครนัส ให้บันทึก ID การรันแบบทึบที่ส่งคืน และ poll `GET /v1/run/{id}` เฉพาะขณะที่สถานะเป็น `pending` หรือ `running`
- ใช้การควบคุมการใช้จ่ายที่มีใน Console สำหรับองค์กรของคุณ

## ข้อผิดพลาดในการชำระเงิน {#payment-errors}

การดำเนินการ API อาจส่งคืน HTTP `402` เมื่อองค์กรไม่สามารถชำระค่าคำขอได้ รูปแบบข้อผิดพลาดแตกต่างกันไปตาม
ส่วนที่เข้ากันได้ของ API จึงควรจัดการตามสถานะ HTTP และออบเจ็กต์ข้อผิดพลาดที่ระบุไว้ แทนการจับคู่กับ
ข้อความใดข้อความหนึ่ง หลังแก้ไขเรื่องการเรียกเก็บเงินใน Console แล้ว ให้ลองใหม่ตามกฎ idempotency และการกู้คืนของการดำเนินการนั้น

งานวิดีโอที่ส่งจะถูกตรวจสอบกับค่าใช้จ่ายโดยประมาณก่อนเริ่มด้วย การเติมเงินครั้งเดียวตั้งแต่ $10 ขึ้นไป
จะเพิ่มระดับบัญชีของคุณ ซึ่งทำให้รันงานวิดีโอพร้อมกันได้มากขึ้น ดู
[ขีดจำกัดการทำงานพร้อมกัน](/guides/concurrency-limits)

[ข้อผิดพลาด](/api-reference/errors)
