# ขีดจำกัดการทำงานพร้อมกัน {#concurrency-limits}

ขีดจำกัดการทำงานพร้อมกันกำหนดจำนวนงานที่องค์กรของคุณมีระหว่างดำเนินการได้ในเวลาเดียวกัน ทุกองค์กรมีระดับบัญชี และระดับนั้นจะกำหนดขีดจำกัดการทำงานพร้อมกัน เมื่อถึงขีดจำกัด การส่งงานใหม่บน endpoint ที่มีการตรวจสอบด้านล่างจะถูกปฏิเสธด้วย `429` จนกว่างานที่กำลังรันอยู่รายการใดรายการหนึ่งจะเสร็จสิ้น โดยงานจะไม่ถูกจัดเข้าคิว

ขีดจำกัดนี้ใช้กับทั้งองค์กร ครอบคลุม API key ทั้งหมด การส่งงานใดที่ถูกตรวจสอบขึ้นอยู่กับ endpoint:

- `POST /v1/run` และการเรียก Platform API ผ่าน `/v1/api/{vendor}/...` จะถูกตรวจสอบสำหรับโมเดลทุกประเภท รวมถึงรูปภาพ เสียง LLM และการดำเนินการ data API
- endpoint อื่น เช่น Chat Completions, Responses, Messages, OpenAI Images และ endpoint ที่เข้ากันได้กับโปรโตคอลของ Gemini และ Volcengine จะตรวจสอบเฉพาะการส่งงานวิดีโอ

## วิธีการทำงาน {#how-it-works}

เมื่อคุณส่งงานที่มีการตรวจสอบ SandBase จะนับจำนวนงานที่องค์กรของคุณกำลังดำเนินการอยู่ ได้แก่งานที่อยู่ในสถานะ `pending` หรือ `running` หากจำนวนนั้นถึงขีดจำกัดแล้ว การส่งงานจะถูกปฏิเสธทันทีด้วย `429` โดยไม่มีการสร้างงานและไม่มีการเรียกเก็บเงิน

การนับครอบคลุมคำขอที่กำลังดำเนินการทั้งหมดในองค์กรของคุณ ไม่ใช่เฉพาะวิดีโอ chat completion แบบสตรีมที่ยังเปิดอยู่ขณะที่คุณส่งงานที่มีการตรวจสอบจะใช้หนึ่งช่อง หากองค์กรเดียวกันรันทั้งแชตแบบสตรีมที่ใช้เวลานานและงานวิดีโอ ให้นับรวมทั้งหมดเมื่อวางแผนความจุ

ช่องจะว่างทันทีที่งานเข้าสู่สถานะสุดท้าย (`completed`, `failed` หรือ `timeout`) โดยคุณไม่ต้องปล่อยช่องเอง เนื่องจากช่องจะว่างเมื่องานเสร็จสิ้น ไม่ใช่ตามตัวจับเวลา `429` นี้จึงแตกต่างจาก[ขีดจำกัดอัตรา](/guides/rate-limiting)ต่อนาที การรอตามระยะเวลาที่กำหนดไม่ได้รับประกันว่าจะได้ช่อง ให้รอจนกว่างานของคุณเองรายการใดรายการหนึ่งจะเสร็จสิ้นแทน

## ขีดจำกัดเริ่มต้น {#default-limits}

ทุกองค์กรใหม่จะเริ่มที่ระดับ **Bronze** ซึ่งมีขีดจำกัด 2 งานพร้อมกัน ระดับของคุณจะเพิ่มขึ้นโดยอัตโนมัติตามจำนวนเงินของการเติมเงินที่สำเร็จในครั้งเดียว

| ระดับ | การเติมเงินครั้งเดียว | งานพร้อมกัน |
|-------|---------------|------------------|
| Bronze | ค่าเริ่มต้น | 2 |
| Silver | $10 ขึ้นไป | 10 |
| Gold | $100 ขึ้นไป | 100 |
| Platinum | $500 ขึ้นไป | 500 |
| Diamond | ติดต่อฝ่ายขาย | ไม่จำกัด |

- **นับจากการเติมเงินครั้งเดียว ไม่ใช่ยอดสะสม** การเติมเงิน $60 สองครั้งจะยังคงอยู่ที่ Silver ส่วนการเติมเงิน $100 ครั้งเดียวจะเลื่อนคุณขึ้นเป็น Gold
- **มีแต่การเลื่อนระดับขึ้น** การเติมเงินที่น้อยกว่าในภายหลังจะไม่ลดระดับของคุณ
- **เฉพาะการเติมเงินที่ชำระจริง** เครดิตโปรโมชัน เครดิตสมัครใช้งาน และคูปองไม่เปลี่ยนระดับของคุณ
- **มีผลทันที** ขีดจำกัดใหม่จะใช้กับการส่งงานวิดีโอครั้งถัดไปเมื่อการชำระเงินสำเร็จ

## การเพิ่มขีดจำกัด {#increasing-your-limit}

วิธีที่ตรงที่สุดในการเพิ่มขีดจำกัดคือการเติมเงินครั้งเดียวให้ถึงเกณฑ์ถัดไปในตารางด้านบน

หากต้องการงานพร้อมกันมากกว่า 500 งาน หรือต้องการวงเงินเครดิตรายเดือน ให้ติดต่อ [contact@sandbase.ai](mailto:contact@sandbase.ai) เกี่ยวกับระดับ **Diamond** ระดับ Diamond ไม่มีขีดจำกัดการทำงานพร้อมกัน โดยทีม SandBase เป็นผู้ตั้งค่า และจะไม่เปลี่ยนแปลงจากการเติมเงิน

## การตรวจสอบเครดิตเมื่อส่งงานวิดีโอ {#credit-check-on-video-submissions}

นอกจากการตรวจสอบการทำงานพร้อมกันแล้ว SandBase จะประมาณค่าใช้จ่ายของงานวิดีโอแต่ละรายการก่อนรับงาน หากค่าประมาณสูงกว่าเครดิตที่ใช้ได้ (ยอดคงเหลือรวมวงเงินเครดิต) การส่งงานจะถูกปฏิเสธด้วย `402` โดยไม่มีการสร้างงานและไม่มีการเรียกเก็บเงิน

- การส่งงานแต่ละครั้งจะตรวจสอบกับยอดคงเหลือปัจจุบัน งานที่ยังรันอยู่ยังไม่ถูกเรียกเก็บเงิน ดังนั้นให้เผื่อยอดไว้เมื่อส่งวิดีโอหลายรายการพร้อมกัน
- หากราคาของโมเดลขึ้นอยู่กับเอาต์พุตที่มีหลังจากรันเท่านั้น จะไม่สามารถประมาณค่าใช้จ่ายล่วงหน้าได้ การส่งงานจะได้รับการยอมรับและเรียกเก็บเงินตามปกติเมื่องานเสร็จสิ้น

## การจัดการข้อผิดพลาดด้านการทำงานพร้อมกัน {#handling-concurrency-errors}

### 429: ถึงขีดจำกัดการทำงานพร้อมกัน {#_429-concurrency-limit-reached}

```http
HTTP/1.1 429 Too Many Requests
Content-Type: application/json

{
  "error": "organization concurrency limit exceeded"
}
```

จะไม่มีการส่งเฮดเดอร์ `Retry-After` เนื่องจากทราบขีดจำกัดล่วงหน้าแล้ว วิธีที่เชื่อถือได้ที่สุดคืออย่าให้เกินขีดจำกัด ให้จำกัดจำนวนงานวิดีโอที่กำลังดำเนินการอยู่ฝั่งไคลเอนต์ และส่งงานถัดไปหลังจากงานก่อนหน้าเสร็จสิ้นเท่านั้น:

::: code-group

```python [Python]
import asyncio

MAX_CONCURRENT_VIDEOS = 2  # set to your level's limit
slots = asyncio.Semaphore(MAX_CONCURRENT_VIDEOS)

async def generate_video(submit, wait_for_result, payload):
    # Hold a slot for the whole lifetime of the task, not just the submit call.
    async with slots:
        task = await submit(payload)
        return await wait_for_result(task)

async def main(submit, wait_for_result, payloads):
    return await asyncio.gather(
        *(generate_video(submit, wait_for_result, p) for p in payloads)
    )
```

```javascript [JavaScript]
const MAX_CONCURRENT_VIDEOS = 2; // set to your level's limit

async function runAll(payloads, submit, waitForResult) {
  const results = [];
  const queue = [...payloads.entries()];

  async function worker() {
    for (let next = queue.shift(); next; next = queue.shift()) {
      const [index, payload] = next;
      // Each worker holds one slot until its task finishes.
      const task = await submit(payload);
      results[index] = await waitForResult(task);
    }
  }

  await Promise.all(
    Array.from({ length: MAX_CONCURRENT_VIDEOS }, worker)
  );
  return results;
}
```

:::

หากยังได้ `429` อยู่ เช่น เพราะมีบริการอื่นในองค์กรเดียวกันส่งงานด้วย ให้ถอยรอแล้วลองใหม่ ใช้ exponential backoff พร้อม jitter และหยุดหลังจากลองครบจำนวนครั้งที่จำกัดไว้ แทนการลองใหม่วนซ้ำถี่ ๆ

### 402: เครดิตไม่พอสำหรับวิดีโอนี้ {#_402-not-enough-credit-for-this-video}

```http
HTTP/1.1 402 Payment Required
Content-Type: application/json

{
  "error": "insufficient credit for estimated video cost"
}
```

อย่าลองใหม่ ให้เติมเงิน หรือเลือกระยะเวลาที่สั้นลงหรือความละเอียดที่ต่ำลงซึ่งมีค่าใช้จ่ายน้อยกว่า

### API ที่เข้ากันได้ {#compatible-apis}

endpoint ที่เข้ากันได้กับโปรโตคอลจะส่งคืนข้อผิดพลาดเหล่านี้ในรูปแบบ native ของตนเอง เช่น endpoint `/api/v3/contents/generations/tasks` ที่เข้ากันได้กับ Volcengine จะส่งคืน `RateLimitExceeded` สำหรับ `429` และ `AccountOverdueError` สำหรับ `402`
