# Обработка ошибок для AI-клиентов {#error-handling-for-ai-clients}

В SandBase нет единой универсальной схемы ошибок. Сначала ветвитесь по HTTP-статусу, затем разбирайте форму ответа,
описанную для соответствующего семейства эндпоинтов. Не рассчитывайте, что каждый ответ содержит `code`, `param`, `request_id` или
определённую строку сообщения.

## Публичные формы ответов {#public-response-shapes}

Основной middleware `/v1/*` и ряд эндпоинтов моделей и ресурсов возвращают плоскую ошибку:

```json
{"error":"organization rate limit exceeded"}
```

Ресурсы платформы Agents (`/v1/agents*`, `/v1/mcp-connections*`, `/v1/secrets*`,
`/v1/skills*`) возвращают объект в стиле OpenAI со стабильным `code`. См. [Ошибки платформы Agents](#agents-platform-errors):

```json
{"error":{"type":"invalid_request_error","code":"invalid_request","param":null,"message":"invalid request"}}
```

OpenAI-совместимые шлюзы сохраняют OpenAI-совместимый формат. `POST /v1/messages` сохраняет
Anthropic-совместимый формат:

```json
{
  "type": "error",
  "error": {
    "type": "invalid_request_error",
    "message": "max_tokens is required"
  }
}
```

## Обработка HTTP-статусов {#http-status-handling}

| Статус | Значение | Действие клиента |
|---|---|---|
| `400` | Недопустимые входные данные или неподдерживаемый параметр | Исправьте запрос по схеме выбранного эндпоинта и модели. |
| `401` | Учётные данные отсутствуют, недействительны, отозваны или истекли | Замените или обновите учётные данные; не повторяйте запрос без изменений. |
| `402` | Запрос невозможно оплатить или достигнут лимит расходов | Решите вопрос с биллингом или лимитами ключа перед повтором. |
| `403` | У учётных данных нет прав, или совместимый интерфейс отображает ошибку расходов в 403 | Изучите описанный формат ответа и используйте ключ с нужными правами. |
| `404` | Модель или ресурс не найдены | Проверьте актуальное имя модели или ID ресурса. |
| `409` | Конфликт состояния ресурса | Прочитайте актуальное состояние ресурса, прежде чем решать, безопасен ли повтор. |
| `429` | Лимит запросов организации или лимит параллельной генерации видео | Повторите с ограниченной экспоненциальной задержкой и джиттером. |
| `500`, `502`, `503`, `504` | Временный сбой SandBase или вышестоящего сервиса | Повторяйте, только если операцию безопасно выполнить повторно. |

## Сообщения аутентификации и ограничения частоты {#authentication-and-rate-limit-messages}

Задокументированные сообщения аутентификации:

- `missing API key in Authorization header`
- `invalid API key`
- `API key has been revoked`
- `API key has expired`

Ключ с ограниченной областью действия, использованный за её пределами, возвращает `403` с вложенным телом: `{"error":{"code":"insufficient_scope","message":"API key is not authorized for this endpoint","request_id":"..."}}`. Ресурсы платформы Agents возвращают тот же `code` в собственном формате.

Задокументированное сообщение об ограничении частоты — `organization rate limit exceeded` (назначенный организации лимит запросов в минуту,
общий для всех её API-ключей). Ответ `429` сейчас не содержит заголовков `Retry-After` или
`X-RateLimit-*`, а универсальных опубликованных значений RPM или параллелизма по умолчанию нет.

## Поиск моделей и ресурсов {#model-and-resource-lookup}

Используйте `GET /v1/models`, чтобы узнать ID доступных моделей, и `GET /v1/models/{id_or_name}`, чтобы проверить модель перед
выполнением. Считайте ID ресурса непрозрачным и проверяйте его соответствующей операцией list или get. Не составляйте
другой URL для опроса на основе префикса ID.

## Алгоритм повторных попыток {#retry-algorithm}

Используйте ограниченную экспоненциальную задержку с джиттером:

```text
delay = min(base_delay * 2^attempt, max_delay) + random_jitter
```

Применяйте следующие правила:

- повторяйте `429` после задержки, вычисленной клиентом;
- повторяйте временные ответы `5xx` лишь небольшое ограниченное число раз;
- не повторяйте без изменений запросы, вернувшие `400`, `401`, `402`, `403` или `404`;
- проверяйте идемпотентность, прежде чем повторять запросы на создание, запуск или внешнее действие;
- сохраняйте частичный вывод при сбое потока и решайте, безопасно ли продолжить или начать заново;
- передавайте вызывающей стороне итоговый HTTP-статус и очищенную ошибку конкретного эндпоинта.

## Ошибки платформы Agents {#agents-platform-errors}

Agents, сессии, Skills, MCP-подключения и секреты возвращают единый формат. Для большинства кодов `message` — фиксированная безопасная фраза; `invalid_request` может содержать краткое пояснение, например какая форма ввода или опция не поддерживается. Ветвитесь по `code`, а не по `message`.

```json
{"error":{"type":"invalid_request_error","code":"conflict","param":null,"message":"conflicting request"}}
```

`type` равен `authentication_error` для 401, `server_error` для 5xx и `invalid_request_error` в остальных случаях.

| HTTP | `code` | Значение | Что делать |
|---|---|---|---|
| 400 | `invalid_request` | Некорректные или неизвестные поля, ошибка валидации или неподдерживаемая опция | Исправьте запрос; не повторяйте без изменений |
| 400 | `skill_not_found` | Указанный Skill или версия недоступны | Исправьте `skills` в Agent |
| 401 | `unauthorized` | Заголовки API-ключа отсутствуют, недействительны или противоречат друг другу | Проверьте `Authorization` / `X-API-Key` |
| 402 | `spending_limit_exceeded` | Исчерпан лимит расходов ключа или баланс организации | Пополните баланс или увеличьте лимит |
| 403 | `insufficient_scope` | Ключ имеет ограниченную область действия и не может использовать ресурсы Agents | Используйте стандартный ключ, созданный в Console |
| 403 | `org_disabled` | Организации не разрешено запускать Agents | Обратитесь в поддержку |
| 404 | `not_found` | Ресурс не существует в вашей организации | Проверьте ID |
| 409 | `conflict` | Устаревший `row_version`, состояние, не допускающее изменения, или `Idempotency-Key`, повторно использованный с другим телом | Прочитайте ресурс заново и примите решение |
| 409 | `session_input_pending` | Предыдущий ввод ещё доставляется | Подождите; не отправляйте повторно с новым ключом |
| 409 | `session_input_expired` | Срок приёма ввода истёк | Изучите историю перед повторной отправкой |
| 409 | `session_environment_unavailable` | Среда выполнения недоступна | Подождите или создайте новую сессию |
| 413 | `request_too_large` | Тело запроса или зафиксированная из него конфигурация сессии превышает лимит размера | Отправьте тело меньшего размера; не повторяйте без изменений |
| 429 | `quota_exceeded` | Превышена квота Agents | Повторите позже |
| 502 | `executor_rejected`, `executor_contract_error` | Слой выполнения отклонил запрос или ответил неожиданным образом | Проверьте конфигурацию Agent и повторите |
| 503 | `executor_unavailable`, `storage_unavailable`, `skill_unavailable`, `tenant_unavailable`, `tenant_provisioning_failed`, `authorization_unavailable`, `admission_unavailable`, `internal_error` | Зависимость временно недоступна | Повторите с задержкой и тем же `Idempotency-Key` |

Также может встретиться `skill_runtime_incompatible`; он возвращается как 503 с сообщением `internal error`.

## Сбои при потоковой передаче {#streaming-failures}

После начала потокового ответа сбой может прийти в формате потока соответствующего протокола, а не в виде нового
HTTP-статуса. Считайте поток неполным, закройте его, сохраните частичное содержимое, нужное приложению, и
повторяйте запрос, только если его безопасно выполнить повторно.
