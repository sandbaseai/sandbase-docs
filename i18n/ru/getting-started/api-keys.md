# API-ключи {#api-keys}

API-ключи аутентифицируют ваши запросы к SandBase. В этом руководстве описано, как создавать ключи, использовать их в запросах и обеспечивать их безопасность.

## Создание API-ключа {#create-an-api-key}

1. Войдите в [SandBase Console](https://www.sandbase.ai/console)
2. Откройте **Developer → API Keys** (или перейдите сразу на страницу [API Keys](https://www.sandbase.ai/console/keys))
3. Нажмите **New key**
4. Введите понятное **Name** (например, «Production Server», «Local Development»)
5. При необходимости задайте **Spending limit** (пустое значение — без ограничений) и дату **Expires** (пустое значение — бессрочно)
6. Нажмите **Create key**
7. Сразу скопируйте ключ из баннера **API key created** — он отображается только один раз

::: danger Важно
API-ключ показывается только один раз, при создании. Если вы его потеряете, придётся создать новый. Сохраните ключ в надёжном месте, прежде чем закрывать диалог.
:::

## Формат ключа {#key-format}

Новые API-ключи, созданные в Console, начинаются с префикса `sk-`, за которым следуют 64 шестнадцатеричных символа:

```
sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

Существующие ключи `sk-sb-...` остаются действительными, пока не истекут или не будут отозваны. Не проверяйте учётные данные
только по префиксу; всегда рассматривайте полное значение как непрозрачный секрет.

## Способы аутентификации {#authentication-methods}

SandBase поддерживает два способа передачи API-ключа в запросах:

### Заголовок Authorization (рекомендуется) {#authorization-header-recommended}

Используйте стандартный заголовок `Authorization: Bearer`. Он совместим с SDK OpenAI и Anthropic:

```bash
curl https://api.sandbase.ai/v1/chat/completions \
  -H "Authorization: Bearer sk-YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "deepseek/deepseek-v4-flash", "messages": [{"role": "user", "content": "Hi"}]}'
```

### Anthropic Messages: заголовок x-api-key {#anthropic-messages-x-api-key-header}

`POST /v1/messages` также принимает нативный заголовок Anthropic `x-api-key`:

```bash
curl https://api.sandbase.ai/v1/messages \
  -H "x-api-key: sk-YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "anthropic/claude-sonnet-5", "max_tokens": 1024, "messages": [{"role": "user", "content": "Hi"}]}'
```

::: tip
Среди шлюзов моделей `x-api-key` читает только `POST /v1/messages`, и при наличии обоих поддерживаемых заголовков
приоритет у него. [Ресурсы платформы Agents](/api-reference/authentication#agents-platform-resources) также принимают
`X-API-Key`. Для всех остальных публичных эндпоинтов используйте заголовок Bearer.
:::

## Права ключей {#key-permissions}

API-ключи SandBase действуют на **уровне организации**:

- Стандартный ключ, созданный в Console, может вызывать публичные ресурсы API, доступные организации
- Использование оплачивается организацией, которой принадлежит ключ
- Для ключа можно задать необязательный срок действия и лимит расходов
- Учётные данные, выпущенные SandBase, например ключи CLI Login, могут иметь ограниченную область действия и возвращают `403` за её пределами

Сейчас Console не позволяет выбирать области действия для стандартного ключа. Ключи CLI Login создаются, когда вы подключаете ИИ-инструмент. На странице API Keys они сгруппированы в одной раскрывающейся строке **CLI Login**, и их нельзя редактировать так же, как стандартные ключи. Ключи, которые SandBase создаёт за вас, отмечены значком **Auto-created**; у них нет лимита на уровне ключа, и их ограничивает баланс аккаунта.

Для каждого ключа в списке отображаются **Name**, **Key Prefix**, **Spent**, **Limit**, **Expires** и **Status**. Чтобы изменить имя, лимит расходов или срок действия стандартного ключа, нажмите **Edit**.

Рассматривайте каждый ключ как учётные данные приложения, а не как личный пароль. Для доступа людей используйте членство в организации, а для рабочих нагрузок — API-ключи.

## Стратегия для окружений {#environment-strategy}

Создавайте отдельный ключ для каждого приложения и окружения:

| Ключ | Пример имени | Зачем |
|---|---|---|
| Локальная разработка | `research-app-dev` | Ротация без прерывания продакшена |
| Staging | `research-app-staging` | Изоляция тестового использования и инцидентов |
| Продакшен | `research-app-production` | Чёткий владелец и ограниченный риск утечки для продакшена |
| Временная автоматизация | `release-check-2026-08` | Задайте срок действия и отзывайте независимо |

Записывайте владельца и развёртывание, которое использует каждый ключ. При ротации разверните новый ключ, убедитесь, что запросы проходят успешно, и только после этого отзовите старый.

## Срок действия и отзыв ключей {#key-expiration-and-revocation}

### Срок действия {#expiration}

При создании ключа можно задать дату окончания срока действия. После её наступления ключ перестаёт работать, а запросы возвращают ошибку `401 Unauthorized`.

Ключи без даты окончания действуют, пока их не отзовут вручную.

### Отзыв ключа {#revoking-a-key}

Чтобы отозвать (отключить) ключ:

1. Перейдите в [Developer → API Keys](https://www.sandbase.ai/console/keys)
2. Найдите ключ, который нужно отозвать
3. Нажмите **Revoke**
4. Подтвердите действие

Отозванные ключи не могут аутентифицировать новые запросы. Отзыв нельзя отменить — если вы отозвали ключ по ошибке, создайте новый.

## Рекомендации по безопасности {#security-best-practices}

### Никогда не добавляйте ключи в систему контроля версий {#never-commit-keys-to-version-control}

Вместо этого используйте переменные окружения или менеджер секретов:

```bash
# .env file (add to .gitignore!)
SANDBASE_API_KEY=sk-your-key-here
```

```python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["SANDBASE_API_KEY"],
    base_url="https://api.sandbase.ai/v1"
)
```

```javascript
import OpenAI from 'openai';

const client = new OpenAI({
  apiKey: process.env.SANDBASE_API_KEY,
  baseURL: 'https://api.sandbase.ai/v1',
});
```

### Используйте разные ключи для разных окружений {#use-separate-keys-for-different-environments}

Создайте отдельные ключи для разработки, staging и продакшена. Так вы сможете отозвать скомпрометированный ключ разработки, не затрагивая продакшен.

### Регулярно ротируйте ключи {#rotate-keys-regularly}

Периодически создавайте новые ключи и выводите старые из использования. Это сокращает период риска в случае утечки ключа.

### Отслеживайте активность {#monitor-activity}

Регулярно проверяйте **Developer → Activities** на предмет неожиданных всплесков запросов или использования: они могут указывать на скомпрометированный ключ. В **Request History** можно фильтровать по API-ключу.

Если ключ раскрыт, немедленно отзовите его, создайте замену, обновите приложение, которое его использует, и проверьте Activities и платёжные данные на неожиданное использование. Не ждите плановой ротации.

### Задавайте срок действия {#set-expiration-dates}

Для временного доступа (конвейеры CI/CD, доступ подрядчиков, демонстрации) задайте дату окончания срока действия, чтобы ключ автоматически перестал работать.

## Устранение неполадок {#troubleshooting}

| Ошибка | Причина | Решение |
|-------|-------|-----|
| `401 - missing API key` | В запросе нет ключа | Добавьте заголовок `Authorization: Bearer <key>` |
| `401 - invalid API key` | Ключ не существует | Проверьте опечатки и убедитесь, что ключ указан полностью |
| `401 - API key has been revoked` | Ключ был безвозвратно отозван в Console | Создайте ключ на замену |
| `401 - API key has expired` | Срок действия ключа истёк | Создайте новый ключ или продлите срок действия |
| `402 - API key spending limit exceeded` | Ключ достиг заданного лимита расходов | Повысьте лимит или используйте другой ключ с нужными правами |
| `403 - insufficient_scope` | Учётные данные с ограниченной областью действия не могут вызывать этот эндпоинт | Используйте ключ с правами на этот эндпоинт |
