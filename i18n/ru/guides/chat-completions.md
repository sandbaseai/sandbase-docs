# Chat Completions {#chat-completions}

SandBase предоставляет OpenAI-совместимый эндпоинт Chat Completions `POST /v1/chat/completions`. Существующие приложения на OpenAI SDK могут работать с SandBase, если изменить API-ключ и базовый URL.

```python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["SANDBASE_API_KEY"],
    base_url="https://api.sandbase.ai/v1",
)
```

## Сообщения и мультимодальный контент {#messages-and-multimodal-content}

Отправляйте сообщения в порядке диалога, используя роли, поддерживаемые выбранным провайдером, — обычно `system`, `developer`, `user`, `assistant` и `tool`. Текст может быть строкой. Модели с поддержкой зрения также принимают части контента, например `text` и `image_url`.

## Потоковая передача {#streaming}

Укажите `stream: true`, чтобы получать Server-Sent Events. Читайте каждое событие `data:` по порядку и объединяйте `choices[0].delta.content`. Поток завершается `data: [DONE]`. Добавьте `stream_options: {"include_usage": true}`, если выбранный провайдер сообщает использование в потоке; иначе данных об использовании может не быть.

## Инструменты {#tools}

Определите вызываемые функции в `tools`. Когда ассистент возвращает `tool_calls`, выполните каждую функцию в своём приложении, затем добавьте сообщение `tool` с соответствующим `tool_call_id` и продолжайте.

## Структурированный вывод {#structured-output}

Используйте `response_format`, чтобы запросить ответ в виде JSON-объекта или по JSON Schema. Поддержка зависит от модели, поэтому проверьте возможности выбранной модели, прежде чем полагаться на строгое соблюдение схемы.

## Параметры, специфичные для провайдера {#provider-specific-parameters}

SandBase использует `model` и `stream` для маршрутизации. Дополнительные OpenAI-совместимые поля запроса сохраняются, если выбранный провайдер использует тот же протокол. Когда SandBase преобразует один протокол в другой, используйте документированные поля или `extra_body`; поддержка зависит от провайдера.

## Ошибки и повторные попытки {#errors-and-retries}

Используйте ограниченную задержку для повторяемых ответов `429` и временных ошибок сервера, только если повторная генерация безопасна. Не повторяйте автоматически некорректные запросы, ошибки аутентификации и запросы, побочные эффекты инструментов которых могли уже произойти. См. [Ошибки и повторные попытки](/guides/error-handling). Полную схему полей и ответа см. в [Chat Completions API](/api-reference/llm-gateway).
