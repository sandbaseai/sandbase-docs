# Ограничения частоты {#rate-limits}

SandBase может назначить вашей организации лимит запросов в минуту. Он общий для всех API-ключей организации
и считается в скользящем окне длиной в одну минуту. Вышестоящие провайдеры моделей также могут возвращать собственные
ответы `429 Too Many Requests`. Не зашивайте квоту в код, если SandBase не назначил её вашей нагрузке.

## Лимит вашей организации {#your-organization-s-limit}
SandBase не публикует единого фиксированного числа запросов в минуту, потому что лимит назначается для каждой организации отдельно. Все
API-ключи организации учитываются в одном и том же лимите, поэтому создание дополнительных ключей его не увеличивает. Сейчас лимит
не отображается ни в публичном API, ни в Console.

Если вашей нагрузке нужен гарантированный или более высокий лимит, обратитесь в поддержку SandBase и укажите организацию, приложение,
ожидаемую стабильную частоту и ожидаемую частоту всплесков. Не проектируйте продакшен-клиент в расчёте на незадокументированное числовое значение по умолчанию.

## Обработка ответа 429 {#handle-a-429-response}

Ответы об ограничении частоты, сгенерированные платформой для `/v1/*`, используют плоское тело ошибки:

```http
HTTP/1.1 429 Too Many Requests
Content-Type: application/json

{"error":"organization rate limit exceeded"}
```

Лимит организации применяется к `POST /v1/run`, `POST /v1/chat/completions`, `POST /v1/responses`, `POST /v1/messages`, `POST /v1/upload`, а также к эндпоинтам Gemini `generateContent`, `streamGenerateContent` и `POST /v1beta/interactions`. Эндпоинты опроса, такие как
`GET /v1/run/{id}`, не учитываются. Протокольно-совместимые эндпоинты возвращают тот же `429` в собственном формате ошибок,
например в формате Anthropic или Google. Ответ, пришедший от провайдера, может использовать формат ошибок совместимого эндпоинта
и содержать заголовки ограничения частоты провайдера.

Заголовки `Retry-After` и оставшейся квоты не гарантируются. Если `Retry-After` присутствует, соблюдайте его. В противном случае используйте
экспоненциальную задержку с джиттером и максимальным числом попыток.

```python
import os
import random
import time

from openai import OpenAI, RateLimitError

client = OpenAI(
    base_url="https://api.sandbase.ai/v1",
    api_key=os.environ["SANDBASE_API_KEY"],
    max_retries=0,
)

def create_with_backoff(**request):
    for attempt in range(5):
        try:
            return client.chat.completions.create(**request)
        except RateLimitError:
            if attempt == 4:
                raise
            delay = min(2 ** attempt, 30) + random.random()
            time.sleep(delay)
```

OpenAI SDK также поддерживает встроенные повторы через `max_retries`. Осознанно выберите либо повторы SDK, либо цикл повторов в приложении,
чтобы повторы не умножались на разных уровнях.

## Повторяйте только безопасные операции {#retry-only-safe-operations}

Повторный запрос инференса может создать вторую генерацию и повлечь дополнительные расходы. Повторяйте его, только если ваше
приложение допускает повторную генерацию. Не повторяйте автоматически запрос, изменяющий состояние, если операция не документирует
идемпотентность или ваше приложение не может доказать, что первая попытка не удалась.

Для потоковых запросов `429` обычно приходит до начала потока. Если байты уже начали поступать, считайте разрыв соединения
прерванной генерацией, а не ошибкой ограничения частоты. Сохраняйте или отбрасывайте частичный вывод в соответствии с
требованиями продукта; повторный запуск создаёт новую генерацию.

## Управление пропускной способностью {#control-throughput}

- Ограничивайте параллелизм, а не отправляйте неограниченный пакет сразу.
- Ставьте всплески работы в очередь и сглаживайте частоту отправки.
- Избегайте дублирующих запросов и кэшируйте повторно используемые результаты, если это допускают требования к приватности и актуальности.
- Используйте отдельные ключи для разграничения владения, контроля расходов и отзыва, а не для обхода лимитов платформы.
- Записывайте эндпоинт, модель, HTTP-статус и очищенное тело ошибки для диагностики.
- Обращайтесь в поддержку SandBase, если нагрузке нужен назначенный или более высокий лимит пропускной способности.

```python
import asyncio

semaphore = asyncio.Semaphore(8)

async def run_one(client, prompt):
    async with semaphore:
        return await client.chat.completions.create(
            model="deepseek/deepseek-v4-flash",
            messages=[{"role": "user", "content": prompt}],
        )
```

Параллелизм — не то же самое, что число запросов в минуту. Настраивайте оба параметра с учётом наблюдаемой задержки и пропускной способности, назначенной
вашему приложению.

::: info Ежедневные бесплатные вызовы API
100 бесплатных вызовов API данных в сутки по UTC — это лимит в биллинге, а не ограничение частоты. Вызовы сверх него
оплачиваются поштучно, а не отклоняются. См. [Ежедневные бесплатные вызовы API](/guides/billing#daily-free-api-calls).
:::

::: tip Видеозадачи
Задания на генерацию видео также ограничены числом задач, которые ваша организация может выполнять одновременно в зависимости от уровня аккаунта.
Такой `429` содержит `organization concurrency limit exceeded` и снимается, когда завершается выполняющаяся задача, а не по таймеру. См.
[Лимиты параллельности](/guides/concurrency-limits).
:::
