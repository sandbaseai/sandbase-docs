# Цены и использование {#pricing-and-usage}

SandBase использует оплату по факту использования (pay-as-you-go). Доступность моделей, формулы цен, множители кэша и плата за отдельные
возможности могут меняться независимо друг от друга, поэтому интеграциям следует читать актуальные метаданные, а не полагаться на скопированные
таблицы цен.

## Ежедневные бесплатные вызовы API {#daily-free-api-calls}

Каждая организация получает 100 бесплатных вызовов API данных (поиск, соцсети, скрапинг, электронная коммерция, финансы) в сутки по UTC. Этот
лимит общий для всех подходящих API данных и всех ключей организации и сбрасывается в 00:00 UTC. LLM и
медиамодели в него не входят. Не входят и некоторые API данных: более дорогие или тарифицируемые по формуле, например некоторые
пакетные эндпоинты, эндпоинты обхода сайтов, Xiaohongshu PGY и маршруты Douyin Xingtu `kol-*`, оплачиваются с первого вызова.
Чтобы проверить инструмент, выполните `sandbase_inspect`: у подходящих инструментов есть `pricing.free_quota`, а инструменты без него всегда
оплачиваются.

- Вызовы в пределах лимита не тарифицируются, и ими может пользоваться даже организация с нулевым балансом.
- После 100-го вызова подходящие вызовы продолжают работать и оплачиваются поштучно по цене, указанной для инструмента. Они не
  отклоняются и не ограничиваются по частоте из-за исчерпания лимита.
- Неиспользованные вызовы не переносятся на следующий день.

В [MCP-инструментах SandBase](/setup/) `sandbase_inspect` помечает подходящие инструменты полем `pricing.free_quota`
(`daily_limit`, `scope`, `resets`). `sandbase_account` возвращает сегодняшний лимит как `free_api_quota` с
`daily_limit`, `used_today`, `remaining` и `resets_at`; `used_today` и `remaining` опускаются, если счётчик
временно недоступен. После расчёта запуска `sandbase_run` и `sandbase_run_get` сообщают `free_quota_status`:
`free` (покрыто лимитом), `overage` (оплачено после исчерпания лимита) или `degraded` (не оплачено,
потому что счётчик лимита был недоступен).

## Управление биллингом в Console {#manage-billing-in-the-console}

В разделе **Developer → Billing** можно посмотреть баланс, купить кредиты, настроить автопополнение, активировать купоны и управлять настройками биллинга, доступными вашей
организации. Откройте **Developer → Activities → Usage**, чтобы увидеть сводку по запросам, токенам и расходам на уровне организации.

::: info Границы публичного API
Эндпоинты баланса, пополнения, экспорта биллинга и использования на уровне организации сейчас не входят в поддерживаемый
публичный API. Не автоматизируйте сетевые запросы Console и не полагайтесь на внутренние маршруты Console.
:::

## Получение актуальных цен моделей {#read-current-model-pricing}

Сначала найдите доступную модель:

```bash
curl 'https://api.sandbase.ai/v1/models?q=gpt' \
  -H "Authorization: Bearer $SANDBASE_API_KEY"
```

Затем запросите её полную карточку модели:

```bash
curl https://api.sandbase.ai/v1/models/deepseek/deepseek-v4-flash \
  -H "Authorization: Bearer $SANDBASE_API_KEY"
```

Эндпоинт списка оптимизирован для поиска и намеренно не содержит подробных цен на токены, кэш и рассуждения.
Подробные цены выбранной модели берите из `model_card` в ответе с деталями. Универсальной формулы,
применимой к каждой LLM, медиамодели, модели эмбеддингов или возможности API, не существует.

## Проверка записанной стоимости задачи {#check-one-task-s-recorded-cost}

Если операция возвращает ID задачи, запросите её запись о расчёте:

```bash
curl https://api.sandbase.ai/v1/tasks/{task_id}/cost \
  -H "Authorization: Bearer $SANDBASE_API_KEY"
```

Ответ отличает текущую `cost` от `estimated_cost` и сообщает, окончателен ли расчёт. Не
используйте `cost` для сверки биллинга, пока `settled` не равно `true`. Записи задач — это оперативные справочные данные, а не
бухгалтерский журнал. Для сверки и долгосрочного хранения используйте записи биллинга и экспорт в CSV в разделе **Developer → Activities → Usage**.

## Практики контроля расходов {#cost-control-practices}

- Перед запуском новой нагрузки получайте актуальную карточку модели.
- Проверяйте `capability_tags`, `supported_modes` и `unified_schema`; более дешёвые альтернативы полезны, только если они
  поддерживают нужное поведение на входе и выходе.
- Ограничивайте лишний контекст промпта и задавайте подходящий лимит выходных токенов, если выбранная модель это поддерживает.
- Учитывайте, что кэширование зависит от модели. Проверяйте карточку модели и возвращаемые поля usage, а не рассчитывайте на скидку
  для всего провайдера.
- Записывайте ID задач только для запроса стоимости задачи; для асинхронной работы через `/v1/run` записывайте возвращённый непрозрачный ID запуска и опрашивайте `GET /v1/run/{id}` только пока статус `pending` или `running`.
- Используйте средства контроля расходов, доступные вашей организации в Console.

## Ошибки оплаты {#payment-errors}

API-операция может вернуть HTTP `402`, если организация не может оплатить запрос. Формат ошибок зависит от
совместимого интерфейса API, поэтому обрабатывайте HTTP-статус и задокументированный объект ошибки, а не сравнивайте одну строку
сообщения. После решения вопроса с биллингом в Console повторите запрос в соответствии с правилами идемпотентности и восстановления для операции.

Задания на генерацию видео перед запуском также проверяются по их оценочной стоимости. Однократное пополнение на $10 или больше
повышает уровень аккаунта, что позволяет одновременно выполнять больше видеозадач. См.
[Лимиты параллельности](/guides/concurrency-limits).

Актуальные публичные контракты см. в разделах [Модели и цены](/for-agents/models), [Стоимость задачи](/api-reference/tasks/cost) и
[Ошибки](/api-reference/errors).
