# Лимиты параллельности {#concurrency-limits}

Лимиты параллельности определяют, сколько задач ваша организация может выполнять одновременно. У каждой организации есть уровень аккаунта, и этот уровень задаёт её лимит параллельности. Когда лимит достигнут, новые отправки в перечисленные ниже проверяемые эндпоинты отклоняются с кодом `429`, пока не завершится одна из выполняющихся задач. В очередь они не ставятся.

Лимит действует на всю организацию, для всех API-ключей. Какие отправки проверяются, зависит от эндпоинта:

- `POST /v1/run` и вызовы Platform API через `/v1/api/{vendor}/...` проверяются для всех типов моделей, включая операции с изображениями, аудио, LLM и API данных.
- Остальные эндпоинты, такие как Chat Completions, Responses, Messages, OpenAI Images и совместимые по протоколу эндпоинты Gemini и Volcengine, проверяют только отправку видеозадач.

## Как это работает {#how-it-works}

Когда вы отправляете проверяемую задачу, SandBase подсчитывает задачи вашей организации, которые сейчас выполняются, то есть находятся в состоянии `pending` или `running`. Если это число уже достигло лимита, отправка сразу отклоняется с кодом `429`. Задача не создаётся, и ничего не списывается.

В подсчёт входят все выполняющиеся запросы организации, а не только видео. Потоковый chat completion, который ещё открыт в момент отправки проверяемой задачи, занимает один слот. Если одна и та же организация запускает длительные потоковые чаты и видеозадачи, учитывайте их все при планировании мощностей.

Слот освобождается, как только задача переходит в конечное состояние (`completed`, `failed` или `timeout`). С вашей стороны ничего освобождать не нужно. Поскольку слоты освобождаются по завершении задач, а не по таймеру, этот `429` отличается от поминутного [ограничения частоты запросов](/guides/rate-limiting). Ожидание фиксированного интервала не гарантирует свободный слот. Вместо этого дождитесь завершения одной из своих задач.

## Лимиты по умолчанию {#default-limits}

Каждая новая организация начинает с уровня **Bronze** с лимитом в 2 параллельные задачи. Уровень повышается автоматически в зависимости от суммы одного успешного пополнения.

| Уровень | Разовое пополнение | Параллельные задачи |
|-------|---------------|------------------|
| Bronze | По умолчанию | 2 |
| Silver | От $10 | 10 |
| Gold | От $100 | 100 |
| Platinum | От $500 | 500 |
| Diamond | Свяжитесь с отделом продаж | Без ограничений |

- **Учитывается разовое пополнение, а не общая сумма.** После двух пополнений по $60 вы остаётесь на уровне Silver. Одно пополнение на $100 переводит вас на уровень Gold.
- **Только повышение.** Последующее пополнение на меньшую сумму никогда не понижает уровень.
- **Только платные пополнения.** Промокредиты, кредиты за регистрацию и купоны не меняют уровень.
- **Вступает в силу сразу.** Новый лимит применяется к следующей отправке видеозадачи после успешной оплаты.

## Повышение лимита {#increasing-your-limit}

Самый прямой способ повысить лимит — одно пополнение, достигающее следующего порога из таблицы выше.

Если вам нужно более 500 параллельных задач или ежемесячная кредитная линия, напишите на [contact@sandbase.ai](mailto:contact@sandbase.ai) об уровне **Diamond**. У уровня Diamond нет лимита параллельности. Его настраивает команда SandBase, и пополнения никогда его не меняют.

## Проверка кредита при отправке видео {#credit-check-on-video-submissions}

Помимо проверки параллельности, SandBase оценивает стоимость каждой видеозадачи до её приёма. Если оценка превышает доступный кредит (баланс плюс кредитная линия, если она есть), отправка отклоняется с кодом `402`. Задача не создаётся, и ничего не списывается.

- Каждая отправка проверяется по текущему балансу. За ещё выполняющиеся задачи плата пока не списана, поэтому оставляйте запас, когда отправляете несколько видео одновременно.
- Если цена модели зависит от результата, который появляется только после выполнения, заранее оценить стоимость невозможно. Такая отправка принимается, а оплата списывается обычным образом после завершения задачи.

## Обработка ошибок параллельности {#handling-concurrency-errors}

### 429: достигнут лимит параллельности {#_429-concurrency-limit-reached}

```http
HTTP/1.1 429 Too Many Requests
Content-Type: application/json

{
  "error": "organization concurrency limit exceeded"
}
```

Заголовок `Retry-After` не отправляется. Лимит известен заранее, поэтому надёжнее всего никогда его не превышать. Ограничьте на стороне клиента число одновременно выполняющихся видеозадач и отправляйте следующую только после завершения предыдущей:

::: code-group

```python [Python]
import asyncio

MAX_CONCURRENT_VIDEOS = 2  # set to your level's limit
slots = asyncio.Semaphore(MAX_CONCURRENT_VIDEOS)

async def generate_video(submit, wait_for_result, payload):
    # Hold a slot for the whole lifetime of the task, not just the submit call.
    async with slots:
        task = await submit(payload)
        return await wait_for_result(task)

async def main(submit, wait_for_result, payloads):
    return await asyncio.gather(
        *(generate_video(submit, wait_for_result, p) for p in payloads)
    )
```

```javascript [JavaScript]
const MAX_CONCURRENT_VIDEOS = 2; // set to your level's limit

async function runAll(payloads, submit, waitForResult) {
  const results = [];
  const queue = [...payloads.entries()];

  async function worker() {
    for (let next = queue.shift(); next; next = queue.shift()) {
      const [index, payload] = next;
      // Each worker holds one slot until its task finishes.
      const task = await submit(payload);
      results[index] = await waitForResult(task);
    }
  }

  await Promise.all(
    Array.from({ length: MAX_CONCURRENT_VIDEOS }, worker)
  );
  return results;
}
```

:::

Если вы всё же получаете `429`, например потому что задачи отправляет и другой сервис той же организации, сделайте паузу и повторите попытку. Используйте экспоненциальную задержку со случайным разбросом и прекращайте попытки после ограниченного их числа, а не повторяйте запрос в плотном цикле.

### 402: недостаточно кредита для этого видео {#_402-not-enough-credit-for-this-video}

```http
HTTP/1.1 402 Payment Required
Content-Type: application/json

{
  "error": "insufficient credit for estimated video cost"
}
```

Не повторяйте запрос. Пополните баланс или выберите меньшую длительность либо более низкое разрешение, которые стоят дешевле.

### Совместимые API {#compatible-apis}

Совместимые по протоколу эндпоинты возвращают эти ошибки в собственном нативном формате. Например, совместимый с Volcengine эндпоинт `/api/v3/contents/generations/tasks` возвращает `RateLimitExceeded` для `429` и `AccountOverdueError` для `402`.
