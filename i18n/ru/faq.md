# Часто задаваемые вопросы {#frequently-asked-questions}

## Что такое SandBase? {#what-is-sandbase}

SandBase помогает Agents взаимодействовать с реальным миром.

Вы можете использовать готовые модели и API, вызывать их из своих AI-инструментов после подключения в разделе AI tools или создавать многократно используемые Agents и запускать их в сессиях.

## Для кого предназначен SandBase? {#who-is-sandbase-for}

SandBase рассчитан в основном на три группы:

- **пользователей AI-инструментов**, которым нужны полезные возможности в Codex, Claude, Cursor или Kiro
- **разработчиков**, которые хотят вызывать модели и API напрямую
- **FDE и команд**, которые создают многократно используемые Agents для клиентов или внутренних процессов

## Где посмотреть доступные возможности? {#where-do-i-browse-capabilities}
Каталог возможностей представлен на сайте SandBase:

- [Модели](https://www.sandbase.ai/models) и [модели изображений и видео](https://www.sandbase.ai/models/image-video)
- [API](https://www.sandbase.ai/apis)
- [Agents](https://www.sandbase.ai/agents)
- [Skills](https://www.sandbase.ai/skills)
В зависимости от типа возможности её можно изучить, протестировать, установить, вызвать или клонировать.

## Что такое AI tools? {#what-is-ai-tools}

Раздел **Build → AI tools** в Console подключает SandBase к AI-инструменту, которым вы уже пользуетесь, например Claude Code, Codex, Cursor или Kiro. Вставьте `set up https://www.sandbase.ai/SKILL.md` в своего агента или выполните `npx -y @sandbaseai/cli@latest connect`. Подключённый инструмент может искать и запускать модели и API из каталога SandBase с оплатой из вашего рабочего пространства. См. [Подключение AI-инструментов](/setup/).

## Что такое Build Agent? {#what-is-build-agent}

В Build Agent вы определяете и тестируете Agent.

Agent объединяет инструкции, модель, Skills и MCP-инструменты в один многократно используемый версионируемый процесс.

## Отличается ли Agent от API? {#is-an-agent-different-from-an-api}
Да. Agent — это версионируемая конфигурация, которую вы редактируете и тестируете, а запускаете, создавая сессию. Ваше приложение может создавать сессии через [Sessions API](/api-reference/sessions/), пока вы продолжаете редактировать Agent.

## Что такое сессии? {#what-are-sessions}
Сессия — это одно выполнение Agent вместе с диалогом, активностью инструментов и выводом.

## Как дать Agent доступ к внешним API? {#how-do-i-give-an-agent-access-to-external-apis}

Подключите внешнюю систему как MCP-сервер и добавьте её в MCP-подключения Agent. Если серверу нужен Bearer-токен, сохраните его через [Secrets API](/agents/api-credentials#with-the-api) как Secret только для записи, привязанный к URL этого сервера. Токены отправляются только на этот сервер и никогда не попадают в промпты или среду выполнения Agent. См. [Учётные данные для MCP-инструментов](/agents/api-credentials).

## Где находятся модели? {#where-do-models-live}

У моделей есть собственный [каталог](https://www.sandbase.ai/models), потому что это важные строительные блоки.

Модель можно вызвать напрямую, использовать из подключённого AI-инструмента или внутри Agent.

## Нужно ли писать код? {#do-i-need-to-write-code}

Не всегда.

[Подключите свой AI-инструмент](/setup/), если хотите пользоваться возможностями в нём без написания кода.

Используйте справочник API, если хотите вызывать SandBase из своего приложения.

Используйте Build Agent, если нужна многократно используемая многошаговая работа.

## Как получить API-ключ? {#how-do-i-get-an-api-key}

Откройте Console, перейдите в **Developer → API Keys** и выберите **New key**.

Используйте ключ так:

```http
Authorization: Bearer sk-YOUR_KEY
```

## Как устроена оплата? {#how-does-billing-work}

SandBase использует кредиты и оплату по факту использования.

Модели, API, Agents и работа среды выполнения могут стоить по-разному. Актуальное использование и цены смотрите в Console.
