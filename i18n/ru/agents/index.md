# Build Agent {#build-agent}

В Build Agent вы определяете и тестируете Agent, а затем решаете, как он будет запускаться.

Agent — это сохранённая версионируемая конфигурация: модель, инструкции, профиль среды выполнения, Skills и MCP-подключения к внешним инструментам. Сохранение Agent не запускает его.

## Что такое Agent {#what-an-agent-is}

| Вопрос | Где задаётся |
|---|---|
| Что он должен делать? | `instructions` |
| Какая модель выполняет работу? | `model`, ID модели из [Models API](/api-reference/models/) |
| Что он умеет? | [Skills](/agents/mcp-tools#skills), версионируемые пакеты инструкций |
| Какие внешние инструменты он может вызывать? | [MCP-подключения](/agents/mcp-tools#mcp-connections), с [учётными данными](/agents/api-credentials), если серверу нужен токен |
| Как он запускается? | В [сессии](/agents/sessions) |

Каждое фактическое изменение создаёт новую неизменяемую версию. Вы можете в любой момент получить список версий и восстановить более раннюю.

## Как запускается Agent {#how-an-agent-runs}

Agent запускается в [сессии](/agents/sessions). Сессия — это ресурс `ses_`, которому вы отправляете ввод и из которого получаете поток событий, будь то интерактивный диалог, тестовый запуск или вызов из вашего приложения. Каждая сессия фиксирует версию Agent, с которой она началась, поэтому вы можете продолжать редактировать Agent, не затрагивая уже существующие сессии.

## Жизненный цикл Agent: черновик → тест в сессии → запуск из приложения → проверка сессий {#agent-lifecycle-draft-→-test-in-a-session-→-run-from-your-app-→-inspect-sessions}

### 1. Черновик {#_1-draft}

Создайте Agent в Console в разделе **Build → Agents** или через [`POST /v1/agents`](/agents/agent-api). Начните с минимального полезного сценария и добавляйте Skills и MCP-подключения, только когда они нужны инструкциям.

### 2. Тест в сессии {#_2-test-in-a-session}

Создайте сессию для Agent, отправьте типичный ввод и изучите вывод, активность инструментов и ошибки. Проверяйте не только успешный сценарий, но и отсутствующий ввод, недоступные инструменты, пустые результаты и требования к формату вывода.

### 3. Запуск из приложения {#_3-run-from-your-app}

Создавайте сессии для протестированного Agent из своего приложения с помощью [Sessions API](/api-reference/sessions/).

### 4. Проверка сессий {#_4-inspect-sessions}

Читайте items и turns каждой сессии через Sessions API, чтобы просмотреть весь диалог, активность инструментов и ошибки.

## Чек-лист для продакшена {#production-checklist}

- `model` использует актуальный ID модели из Models API.
- Skills закреплены за версией, если поведение не должно меняться незаметно.
- MCP-подключения открывают только нужные Agent инструменты через `allowed_tools`.
- Токены хранятся как [Secrets](/agents/api-credentials) и никогда не записываются в инструкции, ввод или метаданные.
- При создании сессии передаётся `Idempotency-Key`, и повторные попытки используют его же.
- После запуска проверяются статус и ошибки сессии.

## Agents из каталога {#catalog-agents}

Публичный [каталог Agent](/api-reference/agents/catalog) содержит Agents, опубликованные SandBase. Agent из каталога можно читать, но чтобы изменить его, сначала клонируйте его в свою организацию через `POST /v1/agents/catalog/{agent_id}/clone`. Клон — это новый приватный Agent, которым вы владеете и который можете запускать.

::: tip Использование OpenAI SDK
Agents, Sessions и Skills следуют OpenAI Agents API, поэтому официальный OpenAI SDK работает с `base_url="https://api.sandbase.ai/v1"`. Проверенные примеры и различия см. в разделе [Совместимость с OpenAI](/agents/openai-compatibility).
:::
