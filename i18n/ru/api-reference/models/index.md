# Models API {#models-api}

Используйте Models API, чтобы найти модели, прежде чем выбирать эндпоинт инференса. Операция получения списка совместима с OpenAI и возвращает компактные записи с идентификацией модели. Запросите одну модель, чтобы получить метаданные SandBase о возможностях, схеме и ценах.

| Операция | Эндпоинт | Документация |
|---|---|---|
| Список моделей | `GET /v1/models` | [Список моделей](./list) |
| Получение одной модели | `GET /v1/models/{id_or_name}` | [Получение модели](./get) |
| Вызов возможности API по пути | `GET/POST /v1/api/{vendor}/{upstream_path}` | [Сквозной вызов API](./api-passthrough) |
| Запуск модели или возможности API | `POST /v1/run` | [Запуск возможности](./run) |
| Получение асинхронного результата | `GET /v1/run/{id}` | [Получение результата запуска](./run-get) |
| Получение асинхронного callback | `webhook_url` в `POST /v1/run` | [Webhook-callback](./run#webhook-callbacks) |
| Просмотр поддерживаемых моделей | — | [Каталог Models](https://www.sandbase.ai/models) |

Чтобы запустить модель, откройте её справочную страницу в [каталоге Models](https://www.sandbase.ai/models); на каждой странице указаны точный идентификатор, поля запроса и цены. На этой странице описаны поиск моделей, единый запуск возможностей, сквозной вызов API, Assets и получение стоимости задач.

`GET /v1/models` поддерживает `q`, `vendor`, `type` и `order`; пагинации нет. Если `type` не указан, по умолчанию используется `llm`, а явно пустой `type=` возвращает все публичные типы моделей. Фильтр `vendor` требует точного совпадения с учётом регистра; `q` — поиск подстроки без учёта регистра. Каждый элемент списка содержит `id`, `object`, `created` и `owned_by`, где `id` — логическое имя модели, используемое в запросах.

Имена моделей могут содержать `/`. При вызове эндпоинта получения модели передавайте эти слеши как разделители пути, например `/v1/models/openai/gpt-5.6-luna`; маршрут сервера воспринимает оставшуюся часть пути как один логический идентификатор. Узнавайте актуальный ID через `GET /v1/models`, а не копируйте идентификатор из старого руководства.

Получив асинхронный ответ `202` от API инференса, опрашивайте `GET /v1/run/{id}` с возвращённым непрозрачным ID. Не выводите префикс ID и не составляйте другой путь опроса на основе заголовков совместимости.
