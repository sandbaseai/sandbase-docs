# Ошибки API {#api-errors}

SandBase использует стандартные коды состояния HTTP, но не предоставляет единого универсального формата тела ошибки. Сначала ветвите логику по статусу HTTP, затем разбирайте схему ответа, описанную для вызванного эндпоинта. Не рассчитывайте на то, что каждая ошибка содержит `code`, `param`, `message` или `request_id`.

## Форматы ответов {#response-shapes}

Базовый middleware и ряд эндпоинтов `/v1/*` возвращают плоскую ошибку:

```json
{"error":"organization rate limit exceeded"}
```

Ресурсы платформы Agents (`/v1/agents*`, `/v1/mcp-connections*`, `/v1/secrets*`, `/v1/skills*`) возвращают объект в стиле OpenAI со стабильным `code`. См. [Ошибки платформы Agents](#agents-platform-errors):

```json
{"error":{"type":"invalid_request_error","code":"invalid_request","param":null,"message":"invalid request"}}
```

Events API для вебхуков (`/events/webhooks*`) возвращает `{"code":<http status>,"message":"..."}`. См. [Вебхуки](/api-reference/webhooks#authentication-and-errors).

OpenAI-совместимые эндпоинты сохраняют OpenAI-совместимый формат. `POST /v1/messages` сохраняет формат, совместимый с Anthropic:

```json
{
  "type": "error",
  "error": {
    "type": "invalid_request_error",
    "message": "max_tokens is required"
  }
}
```

Точные коды состояния и схемы публичной операции см. в [спецификации OpenAPI](/openapi.yaml).

## Обработка статусов HTTP {#http-status-handling}

| Статус | Типичное значение | Действие клиента |
|---|---|---|
| `400` | Некорректные входные данные или неподдерживаемый параметр | Исправьте запрос по схеме эндпоинта и выбранной модели. |
| `401` | Учётные данные отсутствуют, недействительны, отозваны или истекли | Замените или ротируйте учётные данные; не повторяйте запрос без изменений. |
| `402` | Запрос невозможно оплатить или достигнут лимит расходов | Пополните баланс или измените лимит ключа, прежде чем повторять запрос. |
| `403` | У учётных данных нет прав, или совместимый эндпоинт преобразует ошибку оплаты в 403 | Изучите формат ответа конкретного эндпоинта и используйте ключ с нужными правами. |
| `404` | Модель или ресурс недоступны вызывающей стороне | Проверьте актуальный ID модели или ресурса. |
| `409` | Конфликт состояния ресурса | Прочитайте актуальное состояние, прежде чем решать, безопасно ли повторять запрос. |
| `422` | Семантически некорректные входные данные ресурса | Исправьте значения документированных полей. |
| `429` | Лимит запросов организации или лимит параллельных видеозадач | Повторяйте с ограниченной задержкой и случайным разбросом (jitter), если операцию безопасно повторять. |
| `500`, `502`, `503`, `504` | Сбой SandBase или вышестоящего сервиса | Повторяйте только если операцию безопасно повторять. |

Не каждый эндпоинт документирует все статусы из этой таблицы. Определяющей является карта ответов операции в OpenAPI.

## Ошибки аутентификации {#authentication-errors}

Документированные сообщения об ошибках аутентификации:

- `missing API key in Authorization header`
- `invalid API key`
- `API key has been revoked`
- `API key has expired`

Ключ с ограниченной областью действия, использованный вне этой области, возвращает `403` с вложенным телом: `{"error":{"code":"insufficient_scope","message":"API key is not authorized for this endpoint","request_id":"..."}}`. Ресурсы платформы Agents возвращают тот же `code` в собственном формате.

Для стандартных эндпоинтов используйте `Authorization: Bearer $SANDBASE_API_KEY`. `POST /v1/messages` также принимает `x-api-key`; эндпоинты, совместимые с протоколом Google, документируют собственные поддерживаемые заголовки ключей.

Отозванный ключ нельзя включить снова. Создайте новый ключ, обновите приложение, которое его использует, проверьте работу и затем удалите оставшиеся ссылки на старый ключ.

## Ограничения частоты запросов {#rate-limits}

`organization rate limit exceeded` (`429`) означает, что ваша организация достигла назначенного ей лимита запросов в минуту, общего для всех её API-ключей. Эндпоинты, совместимые с протоколами, возвращают эту ошибку в собственном формате. SandBase не публикует единого числового лимита, поскольку лимит назначается для каждой организации отдельно.

Если ответ содержит `Retry-After`, соблюдайте его. В противном случае используйте ограниченную экспоненциальную задержку со случайным разбросом. Способы сглаживания запросов описаны в разделе [Ограничения частоты запросов](/guides/rate-limiting).

Для отправки задач есть две дополнительные проверки. `organization concurrency limit exceeded` (`429`) означает, что у вашей организации уже выполняется столько задач, сколько допускает уровень аккаунта; ограничение снимается, когда выполняющаяся задача завершается. Проверка действует для всех типов моделей в `POST /v1/run` и `/v1/api/*`, а также для отправки видеозадач в других эндпоинтах. `insufficient credit for estimated video cost` (`402`) означает, что оценочная стоимость превышает ваш баланс вместе с кредитной линией; пополните баланс перед повтором. См. [Лимиты параллельности](/guides/concurrency-limits).

## Безопасность повторов {#retry-safety}

Принимайте решение в таком порядке:

1. Определите, произвела ли операция уже видимый извне эффект.
2. Не повторяйте без изменений запросы, вернувшие `400`, `401`, `402`, `403`, `404` или `422`.
3. При `409` прочитайте текущее состояние ресурса, прежде чем повторять запрос.
4. Повторяйте `429` и временные ответы `5xx` лишь небольшое ограниченное число раз.
5. Прежде чем повторить запрос на создание, запуск, загрузку или внешнее действие, убедитесь, что операция идемпотентна или что ваше приложение умеет устранять дубликаты.

Подходящая задержка:

```text
delay = min(base_delay * 2^attempt, max_delay) + random_jitter
```

## Ошибки платформы Agents {#agents-platform-errors}

Agents, Sessions, Skills, MCP-подключения и Secrets возвращают ошибки в едином формате. Для большинства кодов `message` — фиксированная безопасная фраза; `invalid_request` может содержать краткое пояснение, например какой формат входных данных или параметр не поддерживается. Ветвите логику по `code`, а не по `message`.

```json
{"error":{"type":"invalid_request_error","code":"conflict","param":null,"message":"conflicting request"}}
```

`type` равен `authentication_error` для 401, `server_error` для 5xx и `invalid_request_error` в остальных случаях.

| HTTP | `code` | Значение | Что делать |
|---|---|---|---|
| 400 | `invalid_request` | Некорректные или неизвестные поля, ошибка валидации или неподдерживаемый параметр | Исправьте запрос; не повторяйте без изменений |
| 400 | `skill_not_found` | Указанный Skill или его версия недоступны | Исправьте `skills` у Agent |
| 401 | `unauthorized` | Заголовки API-ключа отсутствуют, недействительны или противоречат друг другу | Проверьте `Authorization` / `X-API-Key` |
| 402 | `spending_limit_exceeded` | Исчерпан лимит расходов ключа или баланс организации | Пополните кредиты или повысьте лимит |
| 403 | `insufficient_scope` | Ключ имеет ограниченную область действия и не может использовать ресурсы Agents | Используйте стандартный ключ, созданный в Console |
| 403 | `org_disabled` | Организации не разрешено запускать Agents | Обратитесь в поддержку |
| 404 | `not_found` | Ресурс не существует в вашей организации | Проверьте ID |
| 409 | `conflict` | Устаревший `row_version`, состояние, не допускающее изменение, или `Idempotency-Key`, повторно использованный с другим телом | Прочитайте ресурс заново, затем примите решение |
| 409 | `session_input_pending` | Предыдущий ввод ещё доставляется | Подождите; не отправляйте повторно с новым ключом |
| 409 | `session_input_expired` | Срок приёма ввода истёк | Проверьте историю, прежде чем отправлять снова |
| 409 | `session_environment_unavailable` | Среда выполнения недоступна | Подождите или создайте новую Session |
| 413 | `request_too_large` | Тело запроса или зафиксированная на его основе конфигурация Session превышает допустимый размер | Отправьте тело меньшего размера; не повторяйте без изменений |
| 429 | `quota_exceeded` | Превышена квота Agents | Повторите позже |
| 502 | `executor_rejected`, `executor_contract_error` | Слой выполнения отклонил запрос или ответил неожиданным образом | Проверьте конфигурацию Agent, затем повторите |
| 503 | `executor_unavailable`, `storage_unavailable`, `skill_unavailable`, `tenant_unavailable`, `tenant_provisioning_failed`, `authorization_unavailable`, `admission_unavailable`, `internal_error` | Зависимость временно недоступна | Повторите с задержкой и тем же `Idempotency-Key` |

Также может встречаться `skill_runtime_incompatible`; этот код возвращается как 503 с сообщением `internal error`.

## Сбои при потоковой передаче {#streaming-failures}

После начала потока ошибка может прийти в формате потока соответствующего протокола, а не как новый HTTP-ответ. Считайте поток незавершённым, сохраните частичный вывод, если он нужен приложению, и повторяйте запрос только если повторная генерация безопасна. Не рассчитывайте на то, что все провайдеры отправляют одинаковое завершающее событие или причину завершения.

## Диагностика в эксплуатации {#operational-debugging}

Записывайте эндпоинт, статус HTTP, выбранную модель или ID ресурса, метку времени и любой безопасный идентификатор запроса, возвращённый сервером. Никогда не записывайте в логи заголовки авторизации, API-ключи, значения учётных данных или конфиденциальное содержимое промптов.

Историю запросов организации можно просмотреть в разделе [Developer → Activities](https://www.sandbase.ai/console/activities). Сообщая о постоянном сбое, приложите очищенные метаданные запроса и минимальный воспроизводимый запрос.
