# Models API {#models-api}

Models API を使うと、推論エンドポイントを選ぶ前にモデルを検索できます。一覧の操作は OpenAI 互換で、簡潔な識別情報のレコードを返します。SandBase の機能、スキーマ、料金のメタデータを確認するには、モデルを 1 件取得します。

| 操作 | エンドポイント | ドキュメント |
|---|---|---|
| モデルを一覧表示する | `GET /v1/models` | [モデルの一覧表示](./list) |
| モデルを 1 件取得する | `GET /v1/models/{id_or_name}` | [モデルの取得](./get) |
| パスを指定して API の機能を呼び出す | `GET/POST /v1/api/{vendor}/{upstream_path}` | [API パススルー](./api-passthrough) |
| モデルまたは API の機能を実行する | `POST /v1/run` | [機能の実行](./run) |
| 非同期の結果を取得する | `GET /v1/run/{id}` | [実行結果の取得](./run-get) |
| 非同期のコールバックを受け取る | `POST /v1/run` の `webhook_url` | [Webhook コールバック](./run#webhook-callbacks) |
| サポートされているモデルを閲覧する | — | [Models カタログ](https://www.sandbase.ai/models) |

モデルを実行するには、[Models カタログ](https://www.sandbase.ai/models) からそのモデルのリファレンスページを開いてください。各ページには、正確な識別子、リクエストフィールド、料金が記載されています。このページでは、検索、統合された機能ランナー、API パススルー、アセット、タスクコストの照会について説明します。

`GET /v1/models` は `q`、`vendor`、`type`、`order` をサポートしており、ページネーションはありません。`type` を省略するとデフォルトで `llm` になり、明示的に空の `type=` を指定するとすべての公開モデルタイプが一覧表示されます。`vendor` フィルターは完全一致で大文字と小文字を区別し、`q` は大文字と小文字を区別しない部分文字列検索です。一覧の各項目には `id`、`object`、`created`、`owned_by` が含まれ、`id` はリクエストで使用する論理モデル名です。

モデル名には `/` が含まれることがあります。詳細エンドポイントを呼び出すときは、そのスラッシュをパス区切りとして渡してください（例: `/v1/models/openai/gpt-5.6-luna`）。サーバーのルートは残りのパスを 1 つの論理識別子として扱います。古いガイドから識別子をコピーせず、`GET /v1/models` で現在の ID を確認してください。

推論 API から非同期の `202` レスポンスが返された場合は、返された不透明な ID を使って `GET /v1/run/{id}` をポーリングします。ID のプレフィックスを推測したり、互換ヘッダーから別のポーリングパスを組み立てたりしないでください。
