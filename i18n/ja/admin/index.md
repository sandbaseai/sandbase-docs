# アカウントと請求 {#account-and-billing}

組織の設定によって、利用量の帰属先、アプリケーションの認証方法、支出の監視方法が決まります。

## 管理できる項目 {#what-you-manage}

| 項目 | 用途 |
|---|---|
| [組織](/admin/organizations) | ワークスペースの境界、メンバー、所有権を管理します |
| [API キー](/getting-started/api-keys) | アプリケーション用の認証情報を作成、ローテーション、失効します |
| [請求とクレジット](/admin/billing) | 残高の確認、クレジットの購入、自動チャージの設定、Activities と Analysis での利用状況の確認を行います |
| [料金と利用量](/guides/billing) | モデルの料金、1 日あたりの無料 API 呼び出し、1 タスクあたりのコストを確認します |
| [レート制限](/guides/rate-limiting) | リクエストの上限と安全なリトライ方法を理解します |

## 推奨されるセットアップ {#recommended-setup}

1. 正しい組織で作業していることを確認します。
2. 開発、ステージング、本番で別々の API キーを作成します。
3. キーには、使用するアプリケーションと環境がわかる名前を付けます。
4. 本番環境で最初のリクエストを送ったら、Activities と請求を確認します。
5. 使っていないキーは失効させ、想定外の利用があればすぐに調査します。

## 所有権とアクセス {#ownership-and-access}

API キーと利用量は組織に属します。組織を切り替えると、Console に表示されるリソース、キー、請求のコンテキストが変わります。本番の設定を変更する前に、選択中の組織を確認し、キーのローテーションはそのキーを使うアプリケーションと調整して行ってください。

## セキュリティの基本 {#security-basics}

- キーは環境変数またはシークレットマネージャーに保存します
- キーを Agent の instructions、ソースコード、スクリーンショット、サポートへのメッセージに貼り付けないでください
- アプリケーションと環境ごとに別のキーを使います
- 漏えいした可能性があるキーはすぐに失効させます
- Activities で、想定外のリクエスト量、モデル、エンドポイントがないか監視します
